# AI Eat 项目现状与下一步

更新时间：2026-09-16

本文档是后端继续开发的统一状态入口。它只记录已经核实的事实，不代表允许上传数据或发布网站。

## 项目目录分工

- `E:\AI work\ai-eat-data-pipeline`：QQ 数据采集、商家匹配、本地审核和 approved-only 导出。
- `E:\AI work\ai-eat-server`：PostgreSQL / Supabase 后端、公开目录、推荐、邮箱登录和用户数据。
- `E:\AI work\ai-eat`：现有 React 网页前端；仍使用旧接口和本地假数据，暂未接入新版后端。
- `E:\AI work\ai-eat-miniprogram`：微信小程序原型，按计划最后再处理。

## 已完成且已有代码

- 高德候选商家同步、学生友好审核排序和商家存在性保护。
- 公开餐厅、菜品、评论查询与 `surprise` / `gallery` 推荐结构。
- 半月评分聚合、评论风险评分、商家自评拦截和导入批次回滚。
- Supabase 邮箱注册、登录、刷新、退出、找回密码和服务端 Token 核验。
- 用户偏好、收藏、消费记录、推荐反馈和文字评价投稿的数据结构与接口。
- 私有图片上传意图的申请、确认、预览和删除接口；评价只接受上传意图 ID，并在同一数据库事务内锁定、附加图片。
- Storage 写入策略已在待上线迁移中收紧为精确匹配用户、对象键和未过期意图；客户端删除策略已移除，后端删除只使用服务角色凭证。
- 线上 PostgreSQL 已应用 001–011 号迁移；Data API 默认锁闭。

## 当前真实数据状态

- 线上分店：1004 家，全部仍为 `existence_status=unverified`。
- 线上场所、菜品、公开评论、图片、许可、社交发现线索：均为 0。
- 线上用户投稿、用户评分、偏好、收藏、消费记录和推荐事件：均为 0。
- 本地采集库：7001 篇帖子，其中 499 篇完成抓取、6502 篇延期；2773 条评论。
- 本地评论：17 条 `approved` 且已匹配商家，2756 条仍为 `pending` 且未匹配；上传数量为 0。
- 本地商家候选：35 条，其中 1 条批准、1 条拒绝、33 条待定。

## 尚未完成或不能使用

### P0：上线前验证图片策略

- 012/013 号迁移仍未应用到线上；不得在本地测试通过后直接视为 Supabase Storage 策略已上线。
- 必须在隔离的真实 Supabase/PostgreSQL 环境验证：任意对象键和过期/跨用户意图写入失败、精确意图写入成功、登录用户不能直接删除、服务角色删除可用。
- 管理员审核 API 尚未实现；本阶段没有扩展管理员审核范围。

### P0：迁移安全

- 迁移器已按 `schema_migrations` 只运行待执行版本，并建立了连续的本地 Git 检查点。
- 012/013 虽然仍是待执行迁移，但包含存储权限边界，必须先经独立审查和隔离环境验证，再由用户确认是否应用。

### P1：让真实数据真正可用

- 先核实一小批真实存在的具体店铺/档口，不能把“美食街”或“食堂”当成具体商家。
- 将审核通过的 QQ 评论再次核对匿名化文本和准确分店后，生成 approved-only 包。
- 先预检导入结果，再经用户确认上传；导入后检查公开 API 和整批回滚。
- 建立菜品、价格、口味标签和有权使用的图片；没有真实图片时只返回明确标注的分类示意图。

### P1：完成用户图片与审核闭环

- 真实 Supabase 环境中的私有存储桶、短期签名上传、文件真实格式/大小与用户所有权策略验证。
- 图片尺寸与像素上限、EXIF 清理、异常图片处理和孤儿文件定时清理。
- 管理员角色初始化、评价/图片审核接口、审计日志和最小权限验证。
- 批准评价后生成公开媒体，并验证原始私有对象的保留与清理策略。

### P1：完善推荐闭环

- 当前推荐只使用请求里显式传入的口味、预算、距离等条件；尚未自动读取用户偏好和历史行为。
- 推荐事件虽然能记录，但还没有用于去重、负反馈降权、探索比例或个性化排序。
- 必须先有已确认商家和少量菜品/评论，才能做真实效果验证。

### P2：网页接入与发布

- React 前端仍调用旧版 `/recommend`、`/restaurant/:id`、`/rating`，并保留假餐厅数据。
- 前端定位失败会回退到北京坐标，不符合西南大学范围。
- 需要补齐邮箱登录界面、Token 生命周期、真实推荐卡片、评价/图片投稿和审核状态。
- 完成本地端到端测试、线上预览环境、回滚演练并经用户确认后才能发布。

### P3：微信小程序

- 网站稳定后复用同一后端开发；现在不进入该阶段。

## 推荐执行顺序

1. 独立审查 012/013，并在隔离的真实 Supabase 环境验证 Storage 写入、读取和服务角色删除边界；未经用户确认不应用迁移。
2. 完成管理员评价/图片审核 API、审计日志和公开媒体生成流程。
3. 完成商家小批量真实性核查，先选 20～50 家学生常吃的具体店铺作为首发数据。
4. 重新确认本地 17 条已批准评论；如用户确实已审核更多评论，查明为什么数据库仍有 2756 条 `pending`。
5. 生成 approved-only 包并预检；得到用户最终确认后才导入线上后端。
6. 导入菜品、价格、口味及合法图片，验证公开查询、推荐、评分和回滚。
7. 改造网页前端并在预览环境做端到端测试。
8. 用户确认后发布网站；网站稳定后再处理微信小程序。

## 当前禁止事项

- 不把 `unverified` 商家改成可公开状态。
- 不把 `pending` 评论直接导入线上。
- 不上传采集平台的图片或未经权利确认的用户图片。
- 不在没有测试、备份和回滚验证时运行 012/013 迁移。
- 不在用户最终确认前发布或更新线上网站。
